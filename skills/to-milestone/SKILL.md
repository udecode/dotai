# To Milestone

Read current user authority, vision, source evidence, existing milestones, PRDs and exact human assignments. Use the project's milestone owner/path; otherwise `docs/milestones/<name>.md`.

Record the launch thesis, beneficiary and observable outcome; present evidence and gaps; required product/data/UI/proof surfaces; non-goals; dependencies and assigned owners; pivot conditions; and the next buildable PRD.

Maintain a ranked draft PRD ladder with status, owning document, user consequence, dependency and next action. Re-rank after a material source change or PRD closeout. Bare PRD discovery uses the top eligible queued entry; a stale ladder is repaired instead of followed blindly.

Do not split schema, capture, projection and proof into separate milestone outcomes merely for scheduling or parallelism. A milestone is a coherent launch thesis, not waterfall approval. Preserve exact external/security/migration boundaries when they justify independent delivery.

When publication is authorized, resolve the actual destination project and existing milestone. Maintain one complete map document and a concise milestone description linking its current thesis and next PRD. Read back body, project and milestone metadata. Do not create a duplicate to avoid reconciling existing work.

Finish with the useful source-backed map, next PRD, unresolved dependencies and exact local/published status. No automatic issue creation or implementation.
