# Grill with Vision

Read current scoped human decisions, the product vision if present, the owning plan/milestone and direct source evidence. Use these to resolve an actual unsettled decision; do not reopen settled designs for ceremony.

For each consequential fork, state the decision, recommend an answer, explain the tradeoff and what changes downstream. Ask one focused question when human intent is necessary; investigate observable facts yourself and continue independent work while waiting.

Make the domain concrete: actor, job, canonical record, source, action, state transition, consequence and proof. Separate external source facts, canonical product truth, derived scores/projections, human resolution and permission to deliver. Vendor field names are evidence, not a product ontology.

Challenge overloaded vocabulary with a concrete scenario and a proposed canonical term. Keep the glossary in the existing domain-context owner. Test the decision against missing data, changed facts, temporal validity, permission and reversal where these affect the promised operation.

Challenge both timid slices and unnecessary infrastructure. Prefer one coherent useful outcome; internal guards, queues and proof are usually acceptance work, not separate product goals. Preserve exact human assignments and deferred capabilities.

Record settled decisions and their evidence in the existing plan or owning document. Use `sync-vision` for a durable doctrine change, `to-milestone` for an unsettled delivery ladder and `to-prd` for buildable scope. State remaining decisions clearly. No speculative implementation, automatic tracker publication or numeric confidence theater.
