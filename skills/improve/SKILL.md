# Improve

Use `task` for one scoped improvement run. Invocation requests audit and repair within the current project unless read-only or plan-only is explicit. Preserve human assignments, settled product decisions and deferred capabilities. Editing this skill does not start an improvement run.

Default to one complete iteration. An integer selects up to that many iterations; a positive duration such as `2h` is an upper bound; `forever` means continue useful authorized work in the active runtime until stopped or blocked. Reject malformed/conflicting budgets. None creates scheduling, publication or native goals; use `autogoal` only under a direct or standing user goal request.

Inventory applicable instruction families and authored areas, not just a convenient file sample. In the existing plan record source, governed set, evidence and pending/reviewed/violation/contested/blocked/not-applicable disposition. Relevant lanes include architecture/API, behavior, runtime/performance, tooling/CI, tests/proof, documentation, UI/design, security/data and agent workflow. An absent lane is explicitly not applicable.

Rank opportunities by correctness and durable user/developer benefit, frequency, evidence, complexity removed and implementation/proof cost. Prefer the strongest justified cut over cheap cosmetic churn. One confirmed defect opens an affected-pattern inspection across its real consumers within the authorized scope; deduplicate overlapping sweeps rather than restarting the whole audit.

Select a coherent batch with source owner, acceptance IDs, proof and safe exit. Use `architecture-cleanup` for code shape, `design`/`verify-app` for UI, `technical-writing` for prose and `maintain-workflow` for reusable instruction defects. Known patterns go straight to implementation; an unresolved consequential design uses its relevant method once.

Keep useful deep modules and evidence. Do not delete a failing check to erase a real defect, create a test because a file exists or optimize without a comparable baseline for the complete operation. Existing debt is eligible evidence, not an excuse to ignore authorized scope.

An iteration is complete only when every applicable scoped area and affected sweep is dispositioned and every confirmed actionable defect is repaired with required proof, or reported under an explicit read-only boundary. A green batch or uninvestigated lead cannot close the iteration. Reuse valid evidence on later iterations; do not invent churn to consume a count or deadline.

Use Task's bounded unblocking and eligible-owner traversal. A real deadline can end an incomplete iteration at a coherent verified checkpoint; preserve unfinished scope and do not mark it completed. Remove only this run's unproved speculative changes when necessary, preserving user work. Pause immediately when asked.

Report the strongest findings, changes kept, complexity removed, measured gains and limits, coverage denominator, remaining gaps, completed iterations and actual stop reason. Keep local work, published work and live proof distinct.
