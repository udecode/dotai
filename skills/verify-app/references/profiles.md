# Select the relevant proof profile

## Runtime and journey

Locate the owning runtime and check its real readiness. Use the intended authenticated actor, sanctioned fixture and environment. Verify the user can find and perform the action, the saved transition survives the relevant reload/reopen, the intended consequence occurs and any delivered/exported artifact is correct. Include the failure/access states required by acceptance.

For native downloads, print, file picking, clipboard, browser permissions or OS-specific behavior, use the actual browser/native surface. A headless or mocked substitute must not claim that native behavior passed. If the needed capability is absent, retain the exact missing proof.

## Copy and design

Read the project's design standards and all copy-producing owners in scope, including server/generated content. Inspect rendered hierarchy, action clarity, errors, empty/pending states and meaningful narrow/mobile composition. Challenge redundant copy and useless UI even when controls work. Component APIs and lint cannot prove useful composition.

## Capability and parity

Inventory accepted requirements, source/reference operations, provider interfaces and actual target callers independently. Map complete actor journeys and their artifacts. Classify every scoped capability as supported with proof, partially supported, missing, blocked, deliberately excluded with authority, obsolete with evidence, or unverified. Do not silently sample a request for full coverage.

A list, document viewer and export can be separate capabilities; their aggregate presence does not prove the complete sender/recipient/respond/reopen journey. Keep exact policy or human assignments separate from independent technical gaps.

## Catalog scenes

Use the canonical scene/flow inventory. Verify the actual child route and material query/state, selector, frame/runtime errors, actor, fixture and readiness reason. Loaded frames and source counts are not coverage. Record each required flow edge and neighboring state that changed. Retain unavailable/access-gated/fixture-gap outcomes until real proof changes them.

## Artifacts and external delivery

Inspect the final rendered or received artifact using a suitable viewer/parser and visual proof where layout matters. A provider request, database row or queued status is not receipt. Sending synthetic messages or changing provider settings requires the corresponding user authority; verification does not create it.

## Evidence reuse

Keep original provenance. Reuse an observation only when its relevant implementation, environment, actor/permission, fixture, state and artifact bindings remain valid. Name the invalidating dependency before repeating a pass. One capture may support several criteria; never relabel it as another operation that was not performed.
