# Atlas

Find the project's canonical review catalog or scene inventory, its manifest, fixture preparation and drift checks. Maintain those owners; do not create a second feature map, screenshot archive or product UI. If no catalog exists, record that fact and use `create-verification-skill` only when creation is requested or in scope.

Update affected scenes when routes, material URL states, action/overlay branches, access gates, meaningful responsive/outcome states or fixture contracts change. Pure refactoring and copy already visible in an existing scene need no invented scene.

A scene names a stable identity, real route/tree, exact material state, actor/access prerequisites, sanctioned fixture, action/selector, expected consequence and readiness reason. A flow links complete state transitions. Navigation categories are not evidence that scenes can run.

When repeated manual fixture work blocks an authorized task, repair the existing sanctioned preparation: stable IDs, idempotent creation, real grants/state and scoped cleanup. Do not touch live data without authority. Preserve non-ready status until `verify-app` observes the intended scene.

Modes: maintain within the active product task; audit the complete requested inventory without product repairs; repair the catalog/fixtures when requested; plan-only stops before inspection. Reuse the current plan and respect pauses and human assignments.

Pass exact changed IDs, flow edges, states and prerequisites to `verify-app`. Record real child routes, selectors, runtime errors and ready/unavailable reasons. Source counts and loaded previews cannot certify coverage. Close with updated owners/checks and actual evidence or explicit missing proof.
